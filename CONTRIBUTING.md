# Contributing

1. Create a focused branch and describe the behavior being changed.
2. Keep simulation code offline. Do not add production network integrations, credentials, or real incident data.
3. Preserve strict schema validation, graph-copy isolation, complexity limits, and clear metric names.
4. Add or update tests for behavior changes; run the commands in README before opening a change.
5. Update README or architecture notes when API contracts, metrics, limits, or algorithms change.

Use conventional, descriptive commit messages. Report security issues privately according to `SECURITY.md`.
